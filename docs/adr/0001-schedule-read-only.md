# ADR 0001. Расписание — read-only витрина над БД Тандема

**Статус:** принято · 16.11.2026

## Контекст

ЛКС показывает расписание студентов и преподавателей. Источник данных —
ERP «Тандем.Университет». Изначально ТЗ предполагало полноценный CRUD расписания
в ЛКС, но расписание уже ведётся в Тандеме: дублирование операций создаёт два
источника правды и риск расхождений.

## Решение

1. ЛКС не создаёт, не изменяет и не удаляет занятия.
2. Сервис `education` читает данные из реплики БД Тандема (режим `replica`)
   либо из локального снимка (режим `snapshot`, если реплики нет).
3. Пользователь БД — только `SELECT`; любые операции записи запрещены
   и проверяются тестом `tests/source/test_no_writes.py`.
4. API отдаёт расписание как проекцию: идентификатор записи источника строкой,
   без преобразования, плюс `source.updated_at` и `source.fetched_at`.
5. Журнал (оценки, посещаемость, ведомости) живёт в БД ЛКС и ссылается на занятие
   расписания по `schedule_entry_external_id` — без внешнего ключа между базами.

## Последствия

* Перенос, замена и отмена занятий выполняются в Тандеме; ЛКС показывает их
  с задержкой до 60 секунд (реплика) или до 15 минут (снимок).
* Появляется зависимость от доступности и стабильности схемы источника:
  нужен мониторинг лага и circuit breaker, режим stale-ответа.
* Из API исключены 6 операций записи расписания; журнал и ведомости не затронуты.

## Альтернативы

* **Копировать расписание в ЛКС с редактированием** — отклонено: два источника правды.
* **Интеграция через API Тандема** — оставлено как возможное расширение; на этапе 1
  доступ к БД даёт меньше задержек и не требует доработок на стороне Тандема.
