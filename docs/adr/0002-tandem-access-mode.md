# ADR 0002. Режим доступа к источнику расписания

**Статус:** предложено · 16.11.2026

## Контекст

Нужно выбрать между чтением из реплики БД Тандема и периодическим снимком
в БД ЛКС (ТЗ, 2.2). Ограничения: нагрузка на источник, требования к свежести
данных, наличие реплики.

## Вариант A. Реплика (предпочтительно)

* Свежесть: до 60 секунд (кэш Redis).
* Нет дублирования данных, нет ETL-задачи.
* Требует: read-only пользователь, пул ≤10 соединений, `statement_timeout` 5 с,
  бюджет ≤60 запросов/мин, индексы источника.
* Риск: недоступность реплики → режим stale (данные из кэша) и 503 без снимка.

## Вариант B. Снимок

* Свежесть: 5–15 минут.
* Не нагружает источник в момент запроса пользователя.
* Требует: ETL-задача, таблица-снимок, отслеживание `updated_at`,
  разрешение конфликтов при изменении схемы источника.
* Риск: расхождение с источником внутри окна обновления.

## Решение

Принимается после подтверждения наличия реплики (открытый вопрос 1 ТЗ).
До подтверждения код реализуется с абстракцией `app/source/tandem/client.py`,
чтобы переключение режима было конфигурацией, а не переписыванием слоя.
